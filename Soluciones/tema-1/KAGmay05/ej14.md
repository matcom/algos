## Problema 14
Escoge un problema que no hayamos visto, recorre el ciclo completo de la conferencia 2 sobre él
y consigue que el algoritmo y la cota mínima coincidan. Es el formato de la pregunta larga del examen
final. 

## 1. El problema

Escogi el problema Patching Array de LeetCode


Entrada.
- Un arreglo nums[0..m−1] de enteros positivos, ordenado en forma no decreciente (se permiten repetidos), con m ≥ 0.
- Un entero n ≥ 1.

Definiciones. Para un multiconjunto A de enteros positivos:
- Un entero v es formable con A si existe un submulticonjunto S ⊆ A con Σ S = v.
- A cubre [1, n] si todo v ∈ {1, …, n} es formable con A.

Salida. El menor k ≥ 0 tal que existe un multiconjunto P de k enteros positivos (los parches, contados con multiplicidad) con el que nums ∪ P cubre [1, n].

Casos raros:

| Caso | Qué pasa |
|---|---|
| m = 0 | Solo hay parches. La respuesta es ⌊log₂ n⌋ + 1 (parches 1, 2, 4, …). |
| nums[0] > 1 | El 1 no es formable: el parche 1 es obligatorio. |
| Elementos > n | No sirven para formar nada en [1, n]; son irrelevantes. |
| Repetidos, p. ej. [1,2,2] | Cuentan por separado; cada copia se puede usar una vez. |
| Ya cubre [1, n] | La respuesta es 0. |
| Parches > n | Nunca ayudan; una solución óptima no los usa. |
| nums desordenado | Está fuera de la especificación: el algoritmo asume orden. |

---

## 2. Algoritmo

### Versión base (greedy)

```
miss ← 1; i ← 0; parches ← 0
mientras miss ≤ n:
    si i < m y nums[i] ≤ miss:
        miss ← miss + nums[i]; i ← i + 1
    si no:
        miss ← 2·miss; parches ← parches + 1   // parche con valor miss
devolver parches
```

Idea: miss es el menor valor que todavía no se puede formar. Si el siguiente número es ≤ miss, se usa y extiende el rango cubierto. Si no, se parchea con miss, que es el parche que más extiende el rango sin dejar huecos.

### Versión mejorada (para igualar la cota inferior)

El greedy pierde tiempo cuando encadena muchos parches seguidos: cada uno duplica miss y se hace en una iteración propia. El número de duplicaciones necesarias se puede calcular de golpe. Para eso se usa bl(x), la longitud en bits de x (bl(0) = 0), que equivale a ⌊log₂ x⌋ + 1 para x ≥ 1. En la práctica es int.bit_length en Python o std::bit_width en C++20.

```
miss ← 1; i ← 0; parches ← 0
mientras i < m y miss ≤ n:
    a ← nums[i]
    si a > miss:
        si a > n: salir del bucle            // a y todo lo que sigue son irrelevantes
        t ← bl(⌈a / miss⌉ − 1)               // mínimo t con miss·2^t ≥ a
        parches ← parches + t
        miss ← miss · 2^t                    // desplazamiento: miss << t
    miss ← miss + a; i ← i + 1
t ← bl(⌊n / miss⌋)                           // mínimo t con miss·2^t > n (0 si miss > n)
parches ← parches + t
devolver parches
```

miss nunca supera 2n, así que cabe en una palabra. En Java o C++ hay que declararlo long.

### Implementación 

```python
def minPatches(nums, n):
    miss, patches = 1, 0
    for a in nums:
        if miss > n:
            break
        if a > miss:
            if a > n:
                break
            t = ((a + miss - 1) // miss - 1).bit_length()
            patches += t
            miss <<= t
        miss += a
    patches += (n // miss).bit_length()
    return patches
```

### Trazas

- nums = [1,3], n = 6: el 1 se usa y miss = 2. Luego a = 3 > 2: ⌈3/2⌉ = 2, t = bl(1) = 1, así que hay un parche y miss = 4; al usar el 3, miss = 7. En la fase final, t = bl(0) = 0. Respuesta: 1.
- nums = [1,5,10], n = 20: el 1 se usa y miss = 2. Luego a = 5 > 2: ⌈5/2⌉ = 3, t = bl(2) = 2, así que hay dos parches y miss = 8; al usar el 5, miss = 13. El 10 ≤ 13 se usa y miss = 23. Respuesta: 2.


## 3. Correctitud

Primero se prueba que el greedy base es correcto y óptimo. Después, que la versión mejorada devuelve lo mismo que el greedy.

### Invariante del greedy

Sea C el multiconjunto formado por nums[0..i−1] y los parches añadidos hasta el momento.

(I) Al inicio de cada iteración, todo v ∈ [1, miss) es formable con C, y Σ C = miss − 1.

- Base: C = ∅ y miss = 1. El rango es vacío y la suma es 0.
- Paso. En ambas ramas se añade a C un valor a con 1 ≤ a ≤ miss: o bien a = nums[i] ≤ miss, o bien a = miss.
  - Si v < miss, ya era formable.
  - Si miss ≤ v < miss + a, entonces 0 ≤ v − a < miss. Si v − a = 0, se usa a solo. Si no, se forma v − a con C y se le suma a.
  - La suma nueva es (miss − 1) + a = (miss + a) − 1.

Terminación. En cada iteración miss crece estrictamente, así que el bucle termina.

Validez. Al salir, miss > n, y por (I) nums ∪ P cubre [1, n].

### Optimalidad (argumento de intercambio)

Sean g₁, …, g_k los parches del greedy en el orden en que los añade, y sea O una solución óptima, vista como un multiconjunto de parches.

Lema. Si O contiene g₁, …, g_{j−1}, existe otra solución O' con |O'| = |O| que contiene g₁, …, g_j.

*Prueba.* Considera el momento en que el greedy añade g_j = x. En ese instante:

- (a) Σ C = x − 1 y, por (I), C ∪ {x} cubre [1, 2x − 1].
- (b) Todos los nums no usados son > x, porque el greedy parchea solo cuando nums[i] > miss y nums está ordenado.

O forma x, y para eso solo pueden participar elementos ≤ x. Por (b), los únicos nums que sirven están en C, y C suma solo x − 1 < x. Por tanto, O contiene un parche o ≤ x distinto de g₁..g_{j−1}.

Sea O' = O − {o} + {x}. Toda suma formable con nums ∪ O que no usa o sigue siéndolo. Una suma que sí usa o tiene la forma c + o + d, donde c es la suma de un subconjunto de C y d la de elementos fuera de C ∪ {o}. Como 0 ≤ c ≤ x − 1 y 1 ≤ o ≤ x, se tiene c + o ∈ [1, 2x − 1]. Por (a), c + o se puede formar con C ∪ {x}, y d se forma con los mismos elementos de antes. Entonces O' es una solución factible del mismo tamaño. ∎

Aplicando el lema para j = 1, …, k se obtiene una solución óptima que contiene a g₁, …, g_k. Por tanto, |O| ≥ k, y como el greedy es factible, k es el óptimo.

### La versión mejorada devuelve lo mismo que el greedy

Basta ver que cada bloque de la versión mejorada reproduce una secuencia de iteraciones del greedy.

- Caso a ≤ miss. Es idéntico a la primera rama del greedy.
- Caso miss < a ≤ n. El greedy parchea mientras a > miss; cada parche duplica miss y no se detiene antes, porque miss < a ≤ n. Hace exactamente el mínimo t con miss·2^t ≥ a parches. Ese t es el mínimo con 2^t ≥ ⌈a/miss⌉, y para q ≥ 1, el mínimo t con 2^t ≥ q es bl(q − 1). Después usa a, igual que la versión mejorada.
- Caso a > n ≥ miss. El greedy duplica miss hasta superar n. Como a > n, nunca llega a cumplirse a ≤ miss antes del fin, así que no usa a ni ningún elemento posterior. La versión mejorada sale del bucle y la fase final hace esas mismas duplicaciones.
- Fase final (sin nums útiles). El greedy hace el mínimo t con miss·2^t > n, es decir, con 2^t ≥ ⌊n/miss⌋ + 1, que es bl(⌊n/miss⌋). Si miss > n, da t = 0.

Por tanto, la versión mejorada devuelve exactamente k, que es el óptimo. ∎

## 4. Costo

Greedy base. Cada iteración cuesta O(1). Hay a lo sumo m iteraciones que consumen un elemento de nums. Las demás duplican miss, que empieza en 1 y vale como mucho n mientras el bucle sigue, así que son a lo sumo ⌊log₂ n⌋ + 1.
→ Tiempo Θ(m + log n) en el peor caso. El caso nums = [1], n = 2^w − 1 alcanza el término log n.

Versión mejorada. El bucle principal hace a lo sumo m iteraciones de costo O(1): una división, un bl, un desplazamiento y unas pocas sumas. La fase final también cuesta O(1).
→ Tiempo O(m). Para m = 0, el costo es O(1).

Memoria (ambas versiones). Usan O(1) palabras extra (miss, i, parches, a, t) y la entrada solo se lee.
→ Memoria extra Θ(1), que trivialmente es óptima.


## 5. Cota inferior: Ω(m)

Teorema. Todo algoritmo determinista que resuelve el problema debe leer, en el peor caso, las m posiciones de nums. Por tanto, su tiempo es Ω(m).

*Prueba (argumento de adversario).* Considera la instancia

  I* : nums = [1, 2, 3, …, m],  n = m(m+1)/2.

Primero, su respuesta es 0. Al procesar el elemento k+1, se tiene miss = 1 + k(k+1)/2 ≥ k+1, así que el greedy nunca parchea y termina con miss = n + 1.

Supón ahora que un algoritmo A no lee la posición j al ejecutarse sobre I*. Construye I_j cambiando solo nums[j]:

- Si j ≥ 1, pon nums[j] = j en lugar de j+1. Sigue ordenado, porque nums[j−1] = j. Ahora la suma total es n − 1 < n, así que n no es formable. La respuesta es ≥ 1.
- Si j = 0, pon nums[0] = 2. Sigue ordenado, porque nums[1] = 2 (o m = 1). Ahora todos los elementos son ≥ 2 y el 1 no es formable. La respuesta es ≥ 1.

A es determinista y su ejecución depende solo de los valores que lee. I* e I_j coinciden en todo lo leído (m, n y nums salvo la posición j), así que A sigue el mismo camino y da la misma salida en ambas. Pero las respuestas correctas son distintas (0 y ≥ 1), así que A falla en una de ellas.

Por tanto, A lee las m posiciones en I*, y cada lectura cuesta al menos 1. ∎


## 6. Algoritmo y cota coinciden

| | Tiempo | Memoria extra |
|---|---|---|
| Greedy base | Θ(m + log n) | Θ(1) |
| Versión mejorada | O(m) | Θ(1) |
| Cota inferior | Ω(m) | Ω(1) |

Con la versión mejorada, el problema queda resuelto en Θ(m) de tiempo y Θ(1) de memoria extra, que es óptimo en el modelo asumido. El greedy base no alcanza la cota: cuando m ≪ log n (p. ej. m = 1 y n = 2³¹), gasta ~31 iteraciones donde bastan O(1).

Si el modelo no incluye bl como operación de costo 1 (por ejemplo, si solo permite +, −, ×, ÷ y comparaciones), cada t se puede hallar con búsqueda exponencial más búsqueda binaria sobre el exponente, en O(log(t+1)) operaciones. Como Σ t ≤ log₂ n + 1, por concavidad el costo total queda en O((m+1)·log(1 + log n/(m+1))). Eso es O(m) cuando m ≥ log n, pero en general no iguala la cota Ω(m). De qué operaciones admita el modelo de la conferencia 1 depende el cierre exacto.
